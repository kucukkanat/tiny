Everything in tiny runs in the browser tab. That is the constraint the rest of
the design falls out of: if something cannot run in a tab, it does not go in.
The app is a PWA — installable, offline, manifest and service worker — served as
static files from GitHub Pages.

## Three layers

<Steps>
  <Step title="The shell">
    `@tiny/app`. A `HashRouter`, a sidebar, a top bar, and a list of features. It knows
    nothing about chat, settings, or models — only that a feature has an `id`, a `title`,
    a `Screen`, and maybe a `Sidebar`.
  </Step>
  <Step title="The host">
    `@tiny/host`. The `Extension` and `Tiny` types, an error boundary, two storage
    helpers, and the two stores a feature can't own alone. It is the one package with
    nothing behind it, and the only one every feature may depend on.
  </Step>
  <Step title="The features">
    `extension-chat`, `extension-settings`, `extension-manager` in the bundle, and
    whatever the user installed at runtime — one kind, built the same way by the same
    registry. A feature never imports another feature.
  </Step>
</Steps>

## Where features meet

Nowhere, is the short answer. An extension that needs something it does not own
takes it off `tiny`, and the registry is what put it there — so the two never
appear in the same sentence:

```tsx packages/app/src/extensions.tsx
export const tiny: Tiny = {
  useChats,
  useModel,
  ask: askUser,
  useTools: () => useExtensions().tools,
  useInstructions: () => useExtensions().instructions,
  useActions: () => useExtensions().actions,
  useProviders: () => useExtensions().providers,
}

export const BUNDLED = [
  chat,
  settings,
  manager,
] as const satisfies readonly ExtensionModule[]
```

Chat calls a model without knowing `extension-settings` exists, and runs tools
without knowing where they came from. `extensions.test.ts` fails the build if an
`extension-*` package ever depends on another.

:::tip
Home is the first screen that is actually live, read off the registry rather than
off `BUNDLED`. What ships can be switched off, and a constant would redirect to a
route with no `<Route>` — which the catch-all would then match again.
:::
