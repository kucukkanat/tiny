---
title: State and storage
description: What survives a reload, and which key holds it.
---

The rule: hit reload, and if anything the user would care about is gone, that is
a bug.

| What                     | Where it lives                      |
| ------------------------ | ----------------------------------- |
| Which screen, which chat | the URL — route and params          |
| What was typed or picked | `localStorage`, restored on mount   |
| An open menu, a hover    | memory, and nobody misses it        |

## The keys

| Key                       | Holds                                                        |
| ------------------------- | ------------------------------------------------------------ |
| `tiny.chat.<id>`          | one conversation — messages, title, `updatedAt`               |
| `tiny.draft.<id>`         | an unsent message for that conversation                       |
| `tiny.extension.<id>`     | `{ id, title, version, enabled }` plus a `url` **or** `source` |
| the provider and theme    | endpoint, key, model, and light/dark, written by settings      |

One key per conversation rather than one big list: saving one chat does not
re-serialise the whole history, and two open tabs writing different
conversations do not overwrite each other.

## Reading it back

Everything read out of storage is validated before it is used — conversations by
the AI SDK's own `safeValidateUIMessages`, extension records by a zod schema.
A transcript or a record from an older build gets dropped, not rendered into a
crash.

```ts
import { write } from '@tiny/plugin-host'

write('tiny.thing', json) // false when storage is full, never a throw
```

:::warning
A full store is a real answer, not an edge case. For an extension you wrote in
the app, the source _is_ the extension — so the write happens first and nothing
is shown as saved until it lands.
:::

## Conversations

`conversations.ts` is a module-level store rather than a context: the sidebar and
the screen are siblings under the shell, and both need the same list, live.

```ts
import { saveConversation, removeConversation, useConversations } from './conversations'

const conversations = useConversations() // newest first, undefined while loading
```

A conversation is named after the first thing you said in it, and is stamped
only when a message is added — opening one to read it does not move it up the
list. Deleting it takes its draft with it.

## Migrations

`plugin-tools` used to store one tool per key under `tiny.tool.<id>`. It is gone,
and `packages/plugin-extensions/src/migrate.ts` turns whatever is left of it into
one extension each on first boot. It can be deleted once nobody is upgrading
from a build that had it — which is the point of keeping it in its own file.
