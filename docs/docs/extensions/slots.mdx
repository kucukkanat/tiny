---
title: Every slot
description: The eight things an extension can add, with a runnable example of each.
---

`id` and `title` are required — the id is the route, the title is what the
sidebar calls it. Everything else is optional, and each slot is a feature on its
own: an extension with only `tools` never draws anything, and one with only a
`Screen` never says a word to the model.

| Slot             | What it adds                                     |
| ---------------- | ------------------------------------------------ |
| `Screen`         | a route at `/#/<id>`, and everything under it    |
| `Sidebar`        | your own section of the left rail                |
| `tools`          | functions the model can call mid-answer          |
| `providers`      | another model API, offered in Settings           |
| `actions`        | a button on a highlighted passage of a reply     |
| `messageActions` | a button in the footer of a message, beside Copy |
| `instructions`   | a line in the model's system prompt              |
| `css`            | a stylesheet, adopted while the extension is on  |

Every example below is a whole module in the flavour you write in the app's own
editor: JSX, no TypeScript, and nothing imported but the five specifiers on the
map. Paste one into a blank extension and turn it on. `providers` is the
exception, and its section says why.

## Screen

A page at `/#/<id>`. The shell matches `/<id>/*`, so everything under that
segment is yours — render `<Routes>` and the paths inside are relative to your
own route. It is rendered `<Screen />` with no props, inside an error boundary
named after you, in a `<main>` that already supplies the page padding and the
scroll container.

```jsx
import { Link, Navigate, Route, Routes, useParams } from 'react-router'

export default () => ({
  id: 'counter',
  title: 'Counter',

  // The shell matched /counter/*, so these paths hang off /#/counter.
  Screen: () => (
    <Routes>
      <Route index element={<List />} />
      <Route path=":n" element={<One />} />
      <Route path="*" element={<Navigate to="/counter" replace />} />
    </Routes>
  ),
})

function List() {
  return (
    <div className="mx-auto flex w-full max-w-2xl flex-col gap-3">
      {[1, 2, 3].map((n) => (
        <Link
          key={n}
          to={String(n)}
          data-testid={'counter-open-' + n}
          className="bg-surface rounded-card p-3 text-sm"
        >
          Number {n}
        </Link>
      ))}
    </div>
  )
}

function One() {
  const { n } = useParams()

  return (
    <div className="mx-auto flex w-full max-w-2xl flex-col gap-3">
      <p data-testid="counter-value" className="text-sm">
        Number {n}
      </p>
      <Link to="/counter" data-testid="counter-back" className="text-primary text-sm">
        Back
      </Link>
    </div>
  )
}
```

:::danger
Never mount a router of your own. There is exactly one `react-router` in the page
and a second `<HashRouter>` is a second context — `useNavigate` throws.
`<Routes>` on its own is the whole of it.
:::

Anything the screen needs from the host it closes over, because the component
takes no arguments:

```jsx
export default (tiny) => ({
  id: 'recap',
  title: 'Recap',
  Screen: () => <p className="text-sm">{tiny.useChats().length} conversations.</p>,
})
```

Pick a width rather than filling the room: `max-w-2xl` for anything read or
written, `max-w-5xl` for a grid of things, `max-w-6xl` for an editor beside what
it produced. Measure with `@container` on your own root, never a `md:`
breakpoint — the sidebar is 16rem wide and appears at 768px, so a screen has
735px of room at a 767px window and 480px at 768px, and no viewport query can
see that the sidebar is collapsed.

## Sidebar

Your own section of the left rail, under everyone else's. It is mounted for the
whole session rather than only on your route, and it takes no props — read the
current route with `useLocation`.

Registering one **takes away your row in the sidebar footer**, on the grounds
that a section is already a way in. If nothing in it links to your screen, there
is no way to reach your screen.

```jsx
import { Link, useLocation, useParams } from 'react-router'

// Thumb-sized where there is no cursor, tight where there is — the same
// `h-11 md:h-8` the app's own rows use. The active state rides on `data-active`
// because that is the form of `bg-sidebar-accent` the app already generates.
const ROW =
  'flex h-11 w-full items-center gap-2 rounded-md px-2 text-left text-sm' +
  ' hover:bg-sidebar-accent data-active:bg-sidebar-accent data-active:font-medium md:h-8'

// On a phone the rail is a drawer sitting over the thing you just picked.
// `setOpenMobile` would shut it, but that lives in @tiny/ui, which is not on the
// import map — so press the shell's own toggle, and only where there is a
// drawer to shut.
const closeDrawer = () => {
  if (window.innerWidth >= 768) return
  document.querySelector('[data-testid="sidebar-toggle"]')?.click()
}

// One path segment each: `pathname` is the encoded path, so a name with a
// space in it would never match the comparison below.
const NOTES = ['Groceries', 'Ideas', 'Reading']

export default () => ({
  id: 'notes',
  title: 'Notes',

  Sidebar: () => {
    const { pathname } = useLocation()

    return (
      <div className="flex w-full min-w-0 flex-col p-2">
        <div className="text-ink-3 flex h-8 items-center px-2 text-xs font-medium">
          Notes
        </div>
        <ul>
          {NOTES.map((name) => (
            <li key={name}>
              <Link
                to={'/notes/' + name}
                data-testid={'note-' + name}
                data-active={pathname === '/notes/' + name}
                onClick={closeDrawer}
                className={ROW}
              >
                <span className="truncate">{name}</span>
              </Link>
            </li>
          ))}
        </ul>
      </div>
    )
  },

  // The shell routed /#/notes/*, so the tail is `useParams()['*']` — already
  // decoded by the router.
  Screen: () => (
    <p className="text-ink-2 text-sm">{useParams()['*'] || 'Pick a note on the left.'}</p>
  ),
})
```

:::note
Below 768px the rail is a drawer, and a closed drawer unmounts what is in it —
`useState` in a sidebar section resets every time it opens. Anything worth
keeping goes in the URL or in `localStorage`.
:::

A `Sidebar` with no `Screen` still gets a route; the shell fills it with a
component that renders nothing, so `/#/<id>` exists and is blank.

## tools

Functions the model can call in the middle of an answer. `tool()` is the AI
SDK's own, so what you put in `inputSchema` is both what `execute` is handed and
what the model is told — `.describe()` on a field is the only documentation it
gets, and one shared zod is what keeps that true across the import map.

A name has to be something a provider will accept: `/^[a-zA-Z0-9_-]{1,64}$/`.

```jsx
import { tool } from 'ai'
import { z } from 'zod'

export default () => ({
  id: 'timezones',
  title: 'Timezones',

  tools: {
    time_in: tool({
      description: 'The current local time in a given IANA timezone.',
      inputSchema: z.object({
        zone: z.string().describe('An IANA timezone, e.g. Europe/Istanbul'),
        clock: z
          .enum(['12', '24'])
          .optional()
          .describe('Which clock to read it on. 24 by default.'),
      }),
      // What arrives here is what the schema said, already validated. A zone
      // that does not exist throws, and the throw goes back to the model to
      // try again rather than taking the answer down.
      execute: ({ zone, clock = '24' }) =>
        new Intl.DateTimeFormat('en-GB', {
          timeZone: zone,
          dateStyle: 'medium',
          timeStyle: 'short',
          hour12: clock === '12',
        }).format(new Date()),
    }),
  },
})
```

A tool can ask the person at the keyboard. `tiny.ask` puts the question in the
chat and the call parks until it is answered — nothing times out, because the
agent loop is running in this tab:

```jsx
import { tool } from 'ai'
import { z } from 'zod'

export default (tiny) => ({
  id: 'confirm',
  title: 'Confirm',
  instructions: 'Before anything irreversible, call confirm_step and wait for it.',

  tools: {
    confirm_step: tool({
      description: 'Ask the person at the keyboard to approve a step before taking it.',
      inputSchema: z.object({
        step: z.string().describe('What is about to happen, in one sentence'),
        choices: z.array(z.string()).optional().describe('Buttons to offer'),
      }),
      execute: async ({ step, choices }) => {
        const answer = await tiny.ask(step, choices?.length ? choices : ['Yes', 'No'])
        // Skip answers with an empty string, and it is the only thing that
        // does — Continue stays disabled until something is typed or picked.
        // That is a refusal, not a failure.
        if (answer === '') return { approved: false, answer: 'skipped' }
        return { approved: answer.toLowerCase() === 'yes', answer }
      },
    }),
  },
})
```

The second argument to `execute` is the SDK's own, and `abortSignal` is the one
worth knowing: it fires when the composer's **Stop** is pressed, so a tool that
reaches the network should pass it on.

```js
execute: async ({ city }, { abortSignal }) => {
  const url = 'https://wttr.in/' + encodeURIComponent(city) + '?format=j1'
  const response = await fetch(url, { signal: abortSignal })
  if (!response.ok) throw new Error('wttr.in said ' + response.status)
  const now = (await response.json()).current_condition[0]
  // Hand back what answers the question. The whole payload is 40 kB of noise.
  return { celsius: now.temp_C, description: now.weatherDesc[0].value }
}
```

:::warning
A tool without an `execute` is not a human-in-the-loop tool here. The registry
wraps every tool with one, so a missing `execute` resolves `undefined` and the
model is handed `null`. Use `tiny.ask` for the question you meant to ask.
:::

`tiny.ask` only resolves while chat is on screen — it is chat that renders the
question. Called from another extension's screen, or with no model configured,
the promise simply waits.

### Drawing the result

A tool's answer is a JSON block by default. Hang a `View` on the tool and it
draws its own result instead — a chart, a calendar, a card, a row of images.

```jsx
import { tool } from 'ai'
import { z } from 'zod'

const Bars = ({ output }) => {
  const rows = Array.isArray(output) ? output : []
  const top = Math.max(1, ...rows.map((row) => row.value))

  return (
    <div style={{ display: 'grid', gap: '4px' }}>
      {rows.map((row) => (
        <div
          key={row.label}
          style={{ display: 'flex', alignItems: 'center', gap: '8px' }}
        >
          <span style={{ color: 'var(--ink-2)', fontSize: '12px' }}>{row.label}</span>
          <span
            style={{
              background: 'var(--brand)',
              height: '16px',
              borderRadius: '4px',
              width: `${(row.value / top) * 100}%`,
            }}
          />
        </div>
      ))}
    </div>
  )
}

export default () => ({
  id: 'bars',
  title: 'Bars',
  instructions: 'When numbers are worth comparing, call chart rather than listing them.',

  tools: {
    chart: {
      ...tool({
        description: 'Draw labelled numbers as a bar chart.',
        inputSchema: z.object({
          rows: z.array(z.object({ label: z.string(), value: z.number() })),
        }),
        // A tool that only exists to be drawn: what the model sends is what
        // comes back, and what comes back is what `View` is handed.
        execute: ({ rows }) => rows,
        // Without this the model is handed its own numbers again, and again on
        // every turn after.
        toModelOutput: () => ({ type: 'text', value: 'Drawn.' }),
      }),
      View: Bars,
    },
  },
})
```

`View` is a component, so it is your code running in the chat screen. Six things
are worth knowing before you write one.

**It is only ever called once there is an output.** While the call is still out,
and if it failed, chat draws its own row exactly as before. There is no loading
state to write and no half-arrived data to defend against — and by the same
token there is no way to draw one, now or later.

**Both props are `unknown`.** They have been through storage and back, so a
`.safeParse` at the top is the whole ceremony. Anything that cannot survive
`JSON.stringify` — a `Date`, a `Blob`, a React element — will not reach you.

**The chip stays, shut, underneath.** Nothing is hidden by being drawn: the raw
input and output are one press below every drawing. That is what makes a drawing
that misreports its own tool something a person can catch.

**A throw is caught and named.** The message says which tool crashed, the rest of
the thread survives, and navigating away and back tries again.

**Colour comes from the tokens.** `var(--brand)`, `var(--ink-2)`, `var(--line)`,
`var(--surface)`, `var(--radius)` — a drawing follows the theme without knowing
there is one.

:::warning
Tailwind classes do not work in an extension installed at runtime. Utilities are
generated by scanning files on disk, and a module in `localStorage` is not one —
`grid-cols-7` and `aspect-video` simply will not exist. Inline `style` with
`var(--token)`, or the [`css`](#css) slot. An extension that ships in the build
has no such problem.
:::

Uninstall the extension, or switch it off, and every drawing it made goes back
to being the JSON block it replaced. Nothing in the conversation is lost, because
nothing about the drawing was ever stored — only the tool's input and output are,
and the drawing is made from those again each time.

The weight of a picture belongs to whoever wants one. A charting library, a
calendar, `mermaid` — bundle it into your extension, or `import()` it from a CDN
inside the component and let the service worker cache it. None of it lands on
anyone else's first paint.

## providers

Another model API, offered in Settings beside Anthropic and OpenAI. `label` is
the row, `baseUrl` is where calls go when the endpoint field is left blank,
`model` turns what the user configured into something the SDK can call, and
`models` is what fills the model picker.

**This is the one slot you cannot use from the app's editor.** Nothing on the
import map builds a `LanguageModel` — the `ai` shim is `tool`, `generateText`,
`dynamicTool`, `asSchema` and `jsonSchema`, and no `@ai-sdk/*` package resolves.
A provider has to be bundled, either into the app or into an extension you build
yourself:

```ts
import { createOpenAICompatible } from '@ai-sdk/openai-compatible'
import type { ExtensionModule } from '@tiny/host'
import * as z from 'zod'

const ModelList = z.object({ data: z.array(z.object({ id: z.string() })) })

export default (() => ({
  id: 'groq',
  title: 'Groq',

  providers: {
    // Not `anthropic` or `openai`. Those belong to the build whether Settings
    // is showing or not, and taking one fails the whole extension.
    groq: {
      label: 'Groq',
      baseUrl: 'https://api.groq.com/openai/v1',

      // Called during render, before there is necessarily a key. Build the
      // client, never fetch, and don't throw on a blank key.
      model: ({ baseUrl, apiKey, model }) =>
        createOpenAICompatible({ name: 'groq', baseURL: baseUrl, apiKey })(model),

      // Called only when Settings' Load button is pressed. Throw with something
      // worth reading — the message is what appears under the model picker.
      models: async ({ baseUrl, apiKey }) => {
        const url = `${baseUrl.replace(/\/$/, '')}/models`
        const response = await fetch(url, {
          headers: { Authorization: `Bearer ${apiKey}` },
        }).catch(() => null)
        if (!response) throw new Error(`Could not reach ${url}. Wrong address, or CORS.`)
        if (!response.ok)
          throw new Error(`${url} answered ${response.status} ${response.statusText}`)

        const body = ModelList.safeParse(await response.json().catch(() => null))
        if (!body.success) throw new Error(`${url} did not answer with a model list`)
        return body.data.data.map(({ id }) => id)
      },
    },
  },
})) satisfies ExtensionModule
```

Ship it in the build ([bundling](/extensions/bundling)) and it imports
`@ai-sdk/openai-compatible` from the workspace. Build it with vite
([building](/extensions/building)) and the same file bundles the provider
package into itself — which is what `extension-starter` does for Gemini, and
most of why its built file is 80 kB.

## actions

A button in the bar that appears when a passage of a reply is highlighted.
Tapping one sends the ask straight away, with the passage quoted under it:
`<ask>:\n\n> <the passage>`. Yours are appended after chat's built-in five.

```jsx
export default () => ({
  id: 'plain-english',
  title: 'Plain English',

  actions: [
    { label: 'Plainer', ask: 'Say this again in plain English' },
    { label: 'Example', ask: 'Give one concrete example of this' },
  ],
})
```

Nothing is imported, because an action is plain data. The bar only appears on a
reply — highlighting your own message offers nothing, since selecting what you
wrote is copying, not asking for another go at it.

## messageActions

A button in the footer of a message, beside Copy. Where an `action` can only
ask, this one runs your code — so it can reach the clipboard, keep something,
post it somewhere, or say something back.

It is handed the message it sits under, and the conversation that message is in:

```ts
type Message = {
  readonly id: string
  readonly role: 'user' | 'assistant'
  /** Everything it said out loud, with tool calls and reasoning left out. */
  readonly text: string
}

type Thread = {
  readonly id: string
  readonly title: string
  /** The model name showing in the picker, not the object behind it. */
  readonly model: string
  /** Everything in it, oldest first, the message you were handed included. */
  readonly messages: readonly Message[]
  /** Say something, as you. Once per press, and never while one is arriving. */
  readonly send: (text: string) => void
}
```

```jsx
export default () => ({
  id: 'keeper',
  title: 'Keeper',

  messageActions: [
    {
      label: 'Quote',
      icon: 'copy',
      run: ({ text }) => void navigator.clipboard?.writeText(text.replace(/^/gm, '> ')),
    },
    {
      label: 'Shorter',
      icon: 'wand',
      // Only on a reply, and only on one long enough to be worth shortening.
      // A button that does not apply is better absent than disabled.
      when: ({ role, text }) => role === 'assistant' && text.length > 280,
      run: ({ text }, thread) => thread.send(`Say this in one sentence:\n\n> ${text}`),
    },
  ],
})
```

Both sides get a footer — your own messages included, which is where their Copy
button came from. The one still streaming does not: half a reply is not what an
action was written to be handed.

### What gets drawn

| `icon`           | What you get                                |
| ---------------- | ------------------------------------------- |
| one of the names | the icon this build already draws elsewhere |
| a component      | yours, in the same slot                     |
| any other string | the string itself, so an emoji works        |
| nothing          | the label, as words, in a wider button      |

The names are `add`, `check`, `copy`, `play`, `retry`, `stop`, `trash` and
`wand` — that list and not a nicer one, because every one of them is already in
the bundle for something else, so naming one costs nothing. A ninth would be a
commit and a deploy, which is the thing the component form saves you.

```jsx
messageActions: [
  { label: 'Star', icon: '★', run: () => {} },
  { label: 'Mine', icon: () => <svg viewBox="0 0 24 24">…</svg>, run: () => {} },
  { label: 'Keep', run: () => {} }, // no icon, so the word is the button
]
```

:::note
Return a promise from `run` and the button is out of use until it settles. Throw,
or reject, and the message is shown under the row rather than left in the
console — it is somebody else's code, and a button that silently did nothing is
worse than one that says why.
:::

`when` runs in render, inside chat's screen rather than your own, so a throw in
it is not allowed to take chat down: the button is shown, which is the default
anyway, and whatever is wrong turns up attributed to your label the moment
someone presses it. Keep it to a look at the message you were handed.

:::warning
`thread.send` throws while a reply is still arriving, and again if you call it
twice from one press. Two requests at once do not lose a reply — they interleave
and write both into the one conversation. It throws rather than doing nothing,
because an extension can ask whether this is a good moment and a silent no-op
cannot be asked about.
:::

## instructions

One line added to the model's system prompt. Every live extension's is joined,
blank line between, in fold order.

```jsx
export default () => ({
  id: 'metric',
  title: 'Metric',
  instructions: 'Give measurements in metric units, with imperial in brackets after.',
})
```

This is the one contribution that would otherwise appear nowhere — you would
only ever meet it in the model's behaviour — so the Extensions screen prints it
verbatim, before the switch is turned on.

## css

A stylesheet, adopted on the document while the extension is on and dropped
again when it goes off. It is a real `CSSStyleSheet`, unlayered, so its rules
beat the app's utilities at equal specificity — and it is global, not scoped, so
prefix your selectors.

Write real CSS on the app's own custom properties. Tailwind utilities are
generated at build time by scanning the repo, and a module living in
`localStorage` was never scanned, so a class the app does not already use
produces no CSS at all.

```jsx
export default () => ({
  id: 'ticker',
  title: 'Ticker',

  css: `
    .ticker {
      display: grid;
      gap: 0.5rem;
      padding: 1rem;
      background: var(--surface);
      color: var(--ink);
      border: 1px solid var(--line);
      border-radius: var(--radius);
      box-shadow: var(--elevation-card);
    }
    .ticker-note { color: var(--ink-2); font-size: 0.875rem; }
    .ticker-go { background: var(--brand); color: oklch(100% 0 0); }
  `,

  Screen: () => (
    <div className="ticker" data-testid="ticker">
      <p className="ticker-note">Styled by the extension, in the app's colours.</p>
      <button type="button" className="ticker-go" data-testid="ticker-go">
        Go
      </button>
    </div>
  ),
})
```

Dark mode needs nothing: the theme toggles a class on `<html>` and every colour
name above is redefined under it.

:::warning
Two names that look available and are not. `@import` is dropped — the sheet is
built with `replaceSync`, which discards import rules. And the theme's own
aliases (`--color-brand`, `--radius-card`, `--spacing-control`, `--shadow-card`)
are inlined into utilities at build time and never emitted as custom properties.
Use the palette underneath them: `--surface`, `--inset`, `--hover`, `--ink`,
`--ink-2`, `--ink-3`, `--line`, `--brand`, `--green`, `--orange`, `--red`,
`--radius`, `--elevation-card`, `--elevation-overlay`.
:::

## When two extensions want the same thing

Everything is folded into one list, what ships first, and the rules differ by
slot:

| Both register            | What happens                                                   |
| ------------------------ | -------------------------------------------------------------- |
| the same `id`            | Refused: _"…is a name this build already answers to."_         |
| the same tool name       | First folded wins, silently. Prefix yours.                     |
| the same provider `kind` | Refused: _"…is a dialect this build already answers to."_      |
| `actions`                | Both appear, in fold order.                                    |
| `messageActions`         | Both appear, labels may collide, and both are drawn.           |
| `instructions`           | Both, joined with a blank line.                                |
| `css`                    | Both sheets are adopted. The order between them is not stable. |

A refusal takes the whole extension with it — an installed one shows the message
on its row and everything else keeps loading; one in the build takes the app
down at boot, which is what you want from a build error.

Before the switch goes on, the Extensions screen shows the screen's route, every
tool with its parameters read back out of the compiled schema, every provider,
every action — a message action named, and marked as running its own code — and
the `instructions` in full. `Sidebar` and `css` are not on that
list — see [what an extension can do to you](/extensions/security).
