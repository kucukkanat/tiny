---
title: Wiring plugins together
description: A plugin never imports another plugin. It exports a factory, and the app fills it in.
---

The one structural rule: **a plugin depends on `plugin-host` and nothing else
with `plugin-` in its name.** When it needs something another plugin owns, it
takes that thing as an argument.

## The factory

Instead of exporting a `Plugin`, export a function that returns one:

```tsx packages/plugin-chat/src/index.tsx
export const chat = (options: ChatOptions): Plugin => ({
  id: 'chat',
  title: 'Chat',
  Screen: () => <ChatScreen {...options} />,
  Sidebar: ChatSidebar,
})
```

Then `packages/app/src/plugins.tsx` — the one file where features meet — passes
in what it needs:

```tsx
chat({
  useModel,     // from plugin-settings
  unconfigured, // a link into /settings, which chat may not name itself
  useTools,     // from plugin-extensions
  useSystem,
  useActions,
  Panel: ToolQuestions,
})
```

Chat calls a model without knowing settings exists, and runs tools without
knowing extensions exists. It could be handed a fake model in a test and would
not notice.

## Why the app owns the link

Chat cannot name another plugin's route — `/settings` is not chat's to know — so
the shell writes that sentence:

```tsx packages/app/src/plugins.tsx
const unconfigured = (
  <p className="text-muted-foreground mx-auto max-w-md py-8 text-center">
    Pick an endpoint, key and model in <Link to="/settings">Settings</Link> first.
  </p>
)
```

## Hooks are the interface

`useModel` and `useTools` are hooks, so the factory is called **once, at module
scope**. The same function identity every render is what the rules of hooks
want, and it is what the app gives it.

```tsx
// Right: one call, at module scope.
export const plugins = [chat({ useModel }), settings({ useProviders })] as const

// Wrong: a new function every render is a new hook every render.
const Screen = () => chat({ useModel: () => useModel() }).Screen
```

## The test that enforces it

`packages/app/src/plugins.test.ts` fails the build if a plugin starts importing
another plugin. It is a one-file rule with a one-file guard — which is the only
reason it has held.

:::tip
The same rule applies to extensions, in a stronger form: an extension is a
function of `Tiny`, and `Tiny` is three things. Everything else it needs is
already the platform.
:::
