```sh
bun install
bun dev          # vite dev server
bun test         # unit tests, all packages
bun typecheck
bun lint         # oxlint
bun run format   # prettier
bun run deadcode # knip: what does nothing reach
bun run build    # static files in packages/app/dist
bun run preview
```

## Per package

```sh
bun --filter @tiny/extension-starter build   # → packages/app/dist/extensions/starter.js
```

The docs site is outside the workspace and installs on its own:

```sh
cd docs && bun install && bun dev
```

`bun run measure` in `packages/app` prints first paint — the entry chunk plus
everything `index.html` preloads. That is the number to watch when adding a
dependency, not the precache total: `globPatterns` keeps scripts out of the
precache, so a JS change moves the `index-*.js` line instead.

## Dead code

`bun run deadcode` is knip, configured in `knip.ts`, and it exits non-zero when
it finds something. `bun run deadcode:fix` applies what it can.

:::warning
Read the diff before accepting a fix — it will delete an export you meant to keep
if the only caller is a comment.
:::

The config teaches knip three things rather than ignoring them, because an ignore
also hides the next one:

<Steps>
  <Step title="CSS is compiled down to its @import specifiers">
    So the one place an extension depends on `@tiny/ui` is visible.
  </Step>
  <Step title="The sdk/* shims are declared as entries">
    Nothing imports a rollup input.
  </Step>
  <Step title="packages/ui sets includeEntryExports">
    A wildcard `exports` map makes every component an entry, and entries are
    exempt from the check by default.
  </Step>
</Steps>

What it does not answer: an export used only by its own test still counts as
used. `--production` would catch that, but it does not resolve across workspaces
here.

## Deploying

Push to `main`. `.github/workflows/pages.yml` typechecks, lints, tests, builds
and publishes `packages/app/dist` to GitHub Pages.

It works under `/tiny/` because every path the build emits is relative and
routing is hash-based — no server rewrite, no `base` to keep in sync.
