---
title: Contracts
description: Every type in @tiny/host, and what each one is for.
---

`@tiny/host` is the whole contract between the shell and a feature. One file,
no runtime code beyond an error boundary and two storage helpers — plus a second
entry, `@tiny/host/app`, for the two stores a single feature cannot own alone.

## Extension

```ts
type Extension = {
  readonly id: string
  readonly title: string
  readonly Screen?: ComponentType
  readonly Sidebar?: ComponentType
  readonly tools?: Readonly<Record<string, Tool>>
  readonly providers?: Readonly<Record<string, ProviderSpec>>
  readonly actions?: readonly ChatAction[]
  readonly instructions?: string
  readonly css?: string
}

type ExtensionModule = (tiny: Tiny) => Extension
```

One type however it arrives. The shell renders `Screen` under `/#/<id>` — nested
routes below that are the extension's own — and `Sidebar`, if there is one, in the
sidebar body; everything past them is folded in with what every other extension
registered. `Screen` is optional: a tools-only extension has no page.

`ExtensionModule` is what the module default-exports, and what a package listed
in `packages/app/src/extensions.tsx` exports too. `Screened` is the same type
with `Screen` required — what the shell routes.

## Tiny

```ts
type Tiny = {
  readonly useChats: () => readonly Chat[]
  readonly useModel: () => LanguageModel | undefined
  readonly ask: (question: string, options?: readonly string[]) => Promise<string>
  readonly useTools: () => ToolSet
  readonly useInstructions: () => string | undefined
  readonly useActions: () => readonly ChatAction[]
  readonly useProviders: () => Registry
}
```

What the app hands an extension: the platform it didn't bring, and the fold of
what every extension did. The first three are the platform — conversations, the
configured model, and a question the person at the keyboard answers. The four
below them are the fold, and they exist because the chat that ships is an
extension like any other and had to read them through the same contract.

They are hooks, and `tiny` is one object built once at the app's module scope,
so calling `tiny.useChats()` in a component is as fixed as an import. The
react-hooks lint rule cannot see that; a bundled extension disables it per line
with a reason.

:::note
This type only ever grows. A module sitting in someone's `localStorage` is bound
to the shape it was written against and there is no migration that reaches it —
so `useModel` returns a `LanguageModel` and always will. Weigh an eighth member
against that.
:::

## Chat and ChatAction

```ts
type Chat = {
  readonly id: string
  readonly title: string
  readonly updatedAt: number
  /** Everything said in it, both sides, a blank line between. */
  readonly text: string
}

type ChatAction = {
  readonly label: string
  /** Sent with the highlighted passage quoted under it. */
  readonly ask: string
}
```

A conversation as an extension sees it: what was said, not how it is stored.

## Provider and ProviderSpec

```ts
type Provider = {
  readonly kind: string
  readonly baseUrl: string
  readonly apiKey: string
  readonly model: string
}

type ProviderSpec = {
  readonly label: string
  /** Where calls go when the endpoint field is left blank. */
  readonly baseUrl: string
  readonly model: (provider: Provider) => LanguageModel
  /** What this endpoint serves. Throw with a readable message and it is shown. */
  readonly models: (provider: Provider) => Promise<readonly string[]>
}
```

`Provider` is what the user configured. `ProviderSpec` is the dialect that turns
it into something the SDK can call — Settings offers one row per spec.

## The runtime bits

```tsx
import { Safely, isExtensionId, isToolName, write } from '@tiny/host'

;<Safely name="Chat" resetKey={pathname}>
  <Screen />
</Safely>

write('tiny.thing', json) // false when storage is full, never a throw
isToolName(name) // what a provider will accept, and a model call
isExtensionId(id) // what may become a route
```

Three things every feature needs and none of them may import from each other.
`Safely` is the shell's error boundary — see [the shell](/architecture/shell)
for why it is not optional.
