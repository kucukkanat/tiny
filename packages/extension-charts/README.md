# @tiny/extension-charts

One tool that draws its own result. The model calls `chart` with labelled
numbers, and instead of the usual JSON block the reply gets a bar chart.

It exists to be the smallest working example of the `View` slot — one tool, no
screen, no dependency, and nothing on first paint but the drawing itself.

## What it is

```tsx
tools: {
  chart: {
    ...tool({
      description: 'Draw labelled numbers as a bar chart in the reply.',
      inputSchema: Chart,
      // Nothing to compute: what comes back here is what `View` is handed.
      execute: (input) => input,
      toModelOutput: () => ({ type: 'text', value: 'Drawn.' }),
    }),
    View: Bars,
  },
}
```

A tool whose `execute` returns its input is not a trick. It is how a model asks
for a picture: the arguments _are_ the data, and `View` is what turns them into
something to look at.

`toModelOutput` is why the model isn't handed its own numbers back. Without it
the payload is spent in context twice — once going out, once coming back — and
again on every turn after that.

## What it draws

```
Mon  ███████████░░░░░░░░░░  12
Tue  █████████████████████  23
Wed  ████████░░░░░░░░░░░░░   9
```

Rows and not columns, because a phone is narrow and a label under an upright bar
has nowhere to go. Ordinary elements and not an SVG: a grid already reflows,
already truncates a long label, and its numbers are already selectable.

Values are non-negative and there are at most 24 of them — a bar chart of more
than that is a table, and a bar chart of less than zero needs a baseline this
one doesn't draw.

## Writing your own

The `View` is handed `{ input, output }` and both are `unknown`, because both
have been through storage and back. Parse before you draw:

```tsx
const read = Chart.safeParse(output)
if (!read.success) return <p>Not a chart.</p>
```

There is nothing to explain in that fallback. Chat keeps the raw input and
output one press below every drawing, which is where you look when a drawing
says it can't.

Colour comes from the app's tokens — `var(--brand)`, `var(--ink-2)`,
`var(--line)` — so a drawing follows the theme without knowing there is one.

**This extension ships in the build, so it can use Tailwind classes.** One
installed at runtime cannot: utilities are generated by scanning files on disk,
and a module living in `localStorage` is not one. Write inline `style` with
`var(--token)` there, or use the `css` slot.
